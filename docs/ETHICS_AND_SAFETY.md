# Ethics and Safety

Cybersecurity skills can protect people or harm them. Authorization is the boundary.

## Rules

1. Test only systems you own or systems for which you have explicit written permission.
2. Stay inside the approved target, time, technique and data scope.
3. Use intentionally vulnerable applications and isolated labs for offensive exercises.
4. Never access another person's account, device, network or data without permission.
5. Never deploy malware, steal credentials, bypass payment, disrupt services or hide unauthorized activity.
6. Do not expose real passwords, API keys, personal data or company information in this public repository.
7. Stop immediately if a lab affects a system outside the intended scope.
8. Record findings responsibly and propose fixes.
9. Follow applicable laws, company policies and responsible-disclosure programs.

## Permission checklist

Before any security test, confirm:

- Who owns the system?
- Do I have written permission?
- Which exact hosts, applications and accounts are allowed?
- Which methods are allowed or prohibited?
- When may testing happen?
- Who should be contacted if something goes wrong?
- How must test data and results be protected?

If any answer is unclear, do not test.

## Safe target rule

All offensive exercises in this course will use one of these:

- Your own disposable local virtual machine
- A purpose-built training platform
- An intentionally vulnerable application running locally
- A system explicitly provided for a legal competition or lab

The goal is to understand weaknesses so that you can prevent and fix them.
