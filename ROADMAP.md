# Cybersecurity Roadmap

This roadmap is sequential. Do not rush. Practical understanding is more valuable than memorizing tools.

| Phase | Module | Topic | Practical result |
|---|---:|---|---|
| Foundation | 01 | What is cybersecurity? | Identify assets, threats, vulnerabilities and risks |
| Foundation | 02 | Computers and operating systems | Understand processes, memory, files and permissions |
| Foundation | 03 | Linux fundamentals | Navigate Linux and manage users, files and services |
| Foundation | 04 | Networking fundamentals | Understand IP, ports, protocols, DNS and routing |
| Foundation | 05 | How the web works | Trace browser, DNS, HTTP, server and database flow |
| Core Security | 06 | CIA triad and security controls | Classify controls and security objectives |
| Core Security | 07 | Threats, vulnerabilities and risk | Build a simple risk register |
| Core Security | 08 | Authentication and authorization | Design secure identity and access flows |
| Core Security | 09 | Cryptography fundamentals | Explain hashing, encryption, signatures and TLS |
| Application | 10 | Secure coding foundations | Apply validation, safe errors and secret management |
| Application | 11 | Web security and OWASP Top 10 | Test intentionally vulnerable local applications |
| Application | 12 | API security | Secure REST APIs, tokens, rate limits and CORS |
| Application | 13 | Java and Spring Security | Build a secure Spring Boot API |
| Data | 14 | Database security | Apply least privilege, encryption and audit logging |
| Platform | 15 | Linux server hardening | Harden an authorized Linux VM |
| Platform | 16 | Cloud security | Use shared responsibility, IAM and network controls |
| Platform | 17 | Docker and container security | Scan and harden container images |
| Platform | 18 | DevSecOps | Add SAST, dependency and secret checks to CI |
| Enterprise | 19 | SAP and enterprise security | Understand roles, destinations, tokens and audit risks |
| Defense | 20 | Logging, monitoring and SIEM | Investigate events using structured logs |
| Defense | 21 | Incident response and forensics | Follow preparation-to-lessons-learned workflow |
| Offensive Lab | 22 | Ethical penetration-testing method | Perform scoped tests only in isolated labs |
| Professional | 23 | Security architecture and threat modeling | Produce a threat model for a real application |
| Professional | 24 | Capstone and career preparation | Deliver a secure Java project and security report |

## Capstone

Build and defend a Java Spring Boot application with:

- Authentication and role-based authorization
- PostgreSQL with restricted database permissions
- Input validation and secure error handling
- Secrets outside source control
- Security headers and safe CORS
- Audit logs without sensitive data
- Dependency, source and container scanning
- A threat model, risk register and incident-response plan

## Success standard

A module is complete only when Danesh can:

- Explain the topic in simple words
- Use the important vocabulary correctly
- Complete the lab safely
- Answer the knowledge check
- Connect the concept to a real application
